# lift-journal-bot

Чат подъезда → LLM → Google-таблица: журнал простоев лифтов для претензии управляющей компании.

**Задача.** Лифты в доме ломаются неделями, УК отвечает «обращений не было». Все жалобы лежат в чате подъезда в Telegram, две тысячи сообщений, руками не разобрать. Нужен документ с датами и длительностью простоев.

**Решение.** Юзербот на Telethon читает историю чата и слушает новые сообщения. Всё, что похоже на жалобу по регулярке («лифт», «застрял», «аварийка»…), уходит в Claude Haiku с вопросом: это поломка, починка, информация или ни то ни другое, и про какой лифт (грузовой, малый, оба). Из ответов собираются простои: «сломался» открывает, «заработал» закрывает, без закрытия дольше 7 дней — «конец неизвестен». Результат по HTTP уходит в Google-таблицу через Apps Script, там три листа: простои, сообщения, сводка по лифтам и месяцам.

**Что внутри**
- `lift.py` — сервис и CLI: `login`, `chats`, `report`, `repush`, `rebuild` (пересборка простоев без вызовов модели).
- `selftest.py` — самопроверка разбора на наборе фраз.
- `gsheet-script.js` — Apps Script web app, привязанный к таблице: upsert по ID, листы создаются сами, ручные колонки не трогает.
- `config.example.py` — настройки и секреты.

**Цифры первого прогона.** 2841 сообщение истории, 34 простоя за полтора года, 411 вызовов модели, около 0,5 $.

**Запуск**
```bash
pip install telethon anthropic requests
cp config.example.py /srv/lift/config.py   # заполнить
python lift.py login
python lift.py             # сервис; systemd-юнит по вкусу
```

**Почему юзербот, а не бот.** В чужом чате бота не добавить, а читать историю может только участник. Сессия отдельная, с собственным device name, чтобы не мешать другим скриптам на том же аккаунте.
